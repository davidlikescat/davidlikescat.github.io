1. 키워드란 무엇인가 — 검색창 뒤에 있는 사람의 말 {#1}

키워드는 "사람이 궁금한 것을 검색창에 치는 말"이다. 콘텐츠 제작자가 정하는 주제가 아니라, 독자가 실제로 입력하는 언어다. 이 차이를 인식하는 것이 모든 키워드 전략의 출발점이다.

키워드의 종류

대표(헤드) 키워드

  • 단어 1~2개, 검색량이 많고 경쟁이 치열하다.
  • 예: "Claude Code", "MCP", "AI Agent"
  • 신규 블로그스팟 블로거에게는 사실상 진입 불가 영역이다.

세부(롱테일) 키워드

  • 단어 3개 이상, 검색량은 적지만 의도가 구체적이고 경쟁이 약하다.
  • 예: "Claude Code로 파이썬 자동화하는 법", "MCP 서버 직접 만들기 예제", "Claude Code vs Cursor 비교"
  • 낮은 도메인권위(DA)를 가진 블로그스팟이 현실적으로 노릴 수 있는 전장이다.
  • 전환율이 대표 키워드보다 높다(독자 의도가 명확하기 때문).

키워드 유형 비교표

유형 단어 수 월간 검색량 경쟁 강도 전환율 블로그스팟 적합성
대표 키워드 1~2개 높음 매우 높음 낮음 X
중형 키워드 2~3개 중간 중간 중간 조건부
롱테일 키워드 3개 이상 낮음 낮음 높음 최적

2. 검색 의도 분류 — 의도를 모르면 키워드를 알아도 소용없다 {#2}

동일한 키워드라도 사람마다 찾는 것이 다르다. 검색 의도를 먼저 파악해야 콘텐츠 형식을 결정할 수 있다.

검색 의도 3분류 (AI 툴 분야 예시)

[주의] 정보형 4060%, 탐색형 2030%, 거래형 10~20%는 분야마다 다르며 정확한 비율은 확정 데이터가 없다. 분류 자체를 도구로 쓰되 비율에 집착하지 말 것.

정보형 (Informational)

  • 사용자 목적: 배우고 싶다, 이해하고 싶다
  • 키워드 패턴: "~란 무엇인가", "~하는 법", "~차이점", "~예제"
  • 콘텐츠 형식: 튜토리얼, 개념 설명, 비교글, 가이드
  • AI 분야 예: "Agentic AI가 일반 AI와 다른 점", "Claude Code 설치 방법", "MCP server 작동 원리"

탐색형 (Navigational)

  • 사용자 목적: 특정 사이트·페이지를 찾고 있다
  • 키워드 패턴: 브랜드명 + 기능, 공식문서
  • 콘텐츠 형식: 랜딩 페이지, 브랜드 소개글
  • AI 분야 예: "Claude Code 공식문서", "Anthropic Claude API"

거래형/행동형 (Transactional / Commercial)

  • 사용자 목적: 구체적 행동을 취하려 한다(다운로드, 가입, 구매, 설치)
  • 키워드 패턴: "~무료", "~다운로드", "~요금제", "~추천", "~vs ~"
  • 콘텐츠 형식: 비교글, 리뷰, 추천 글
  • AI 분야 예: "Claude Code 무료 vs 유료", "Cursor vs Claude Code 어느게 나을까", "MCP 호스팅 서버 추천"

의도별 콘텐츠 전략표

의도 제목 패턴 본문 구성 CTA
정보형 "~하는 법 (단계별)" 개념 → 이유 → 실행 순서 → 예시 코드 관련 글 내부링크
탐색형 "공식 가이드·정리" 요약 + 원본 링크 공식 사이트 유도
거래형 "A vs B 비교", "추천" 장단점 표 → 상황별 픽 직접 실행 유도

3. 도구별 사용법 — 무엇이 무엇을 보여주는가 {#3}

도구 전체 비교표

도구 제공 값 특성 비용
구글 트렌드 0~100 상대지수 트렌드 모멘텀, 시즌성, 지역 분포 무료
구글 키워드플래너 월간 평균 검색량, CPC, 경쟁도 절대 검색량, 광고 계정 필요 무료(계정)
구글 Search Console 실제 노출수·클릭수·순위 내 블로그 실측 데이터 무료
네이버 데이터랩 0~100 상대지수 한국 수요 트렌드, 절대량 아님 무료
네이버 검색광고 키워드도구 PC/모바일 월간 검색수, CPC 절대 검색량, 네이버 광고 계정 필요 무료(계정)
블랙키위 경쟁도, 연관 키워드 한국 블로거용 편의 도구 무료/유료

3-1. 구글 트렌드 사용법

핵심 특성: 0~100 상대지수. 100은 해당 기간 해당 키워드의 최고 관심도 시점이며, 절대 검색량이 아니다.

단계별 사용법:

  1. trends.google.com 접속
  2. 검색창에 키워드 입력 (예: "Claude Code")
  3. 지역: 대한민국 또는 전세계(영문 키워드면 전세계 설정)
  4. 기간: 최근 12개월 → 트렌드 방향 파악, 최근 90일 → 단기 모멘텀
  5. "급상승 검색어" 탭: 기간 내 검색량 증가폭이 가장 큰 키워드. 5000% 초과는 "Breakout"으로 표시.
  6. 최대 5개 키워드를 동시 비교해 상대 모멘텀 가늠 가능.
  7. "연관 검색어" → "급상승(Rising)" 모드: 트렌드 선점 신호.

AI 분야 활용법:

  • 신모델 발표(Anthropic, OpenAI 등) 직후 관련 키워드 급상승 패턴 포착
  • "Can AI..." / "How to + AI" 형태의 질문형 검색이 급상승 트렌드 (구글 Think 1차 출처 확인)
  • 영문·한글 키워드를 각각 입력해 어느 언어가 더 상승 중인지 파악

3-2. 구글 키워드플래너 사용법

핵심 특성: 절대 월간 검색량 + 경쟁도(낮음/중간/높음) + 상단 입찰가(CPC) 제공.

단계별 사용법:

  1. Google Ads 계정 생성 (무료, 광고 집행 불필요)
  2. 도구 → 키워드플래너 → "새 키워드 검색"
  3. 키워드 입력 → 지역/언어/기간 설정
  4. 확인 컬럼: 월간 평균 검색수, 3개월·전년 대비 변동, 경쟁 정도, 상단 입찰가
  5. 연관 키워드 목록에서 롱테일 후보 발굴

주요 컬럼 해석:

  • 월간 평균 검색수: 범위로 표시(예: 1K~10K). 정확한 수치는 광고 집행 계정에서 확인.
  • 경쟁 정도: 광고주 경쟁 기준. SEO 경쟁과 다를 수 있으나 참고지표로 유효.
  • 3개월 변동: 상승 중인 키워드 발굴에 유용.

3-3. 구글 Search Console 사용법

핵심 특성: 내 블로그스팟에 실제로 발생한 노출·클릭·순위를 보여주는 유일한 도구.

단계별 사용법:

  1. search.google.com/search-console
  2. 블로그스팟 URL 속성 등록 (블로그스팟은 URL prefix 방식 권장)
  3. "실적" 탭 → 쿼리(검색어) 목록 확인
  4. 노출 있지만 클릭률(CTR) 낮은 쿼리 → 제목/설명 최적화 대상
  5. 순위 6~15위 쿼리 → 재최적화 우선순위 (조금만 올려도 클릭 급증)

블로그스팟 등록 전 필수: Blogger 설정 → 개인정보 보호 → "검색엔진에 표시됨" ON 확인 (이것이 꺼져 있으면 구글에 색인 자체가 안 됨).

3-4. 네이버 데이터랩 사용법

핵심 특성: 구글 트렌드와 동일한 0~100 상대지수. 절대 검색량이 아니다. 시간대별·연령별·성별 세분화는 제공하지 않음(반증된 정보).

단계별 사용법:

  1. datalab.naver.com 접속
  2. 검색어 트렌드 → 키워드 입력
  3. 기간·기기(PC/모바일)·성별·연령 설정 → 그래프 비교
  4. 활용: 두 키워드("Claude Code" vs "클로드 코드")를 같은 그래프에 넣어 한국 수요 비교

한계: 절대 검색량이 필요하면 네이버 검색광고 키워드도구 사용.

3-5. 네이버 검색광고 키워드도구 사용법

핵심 특성: PC/모바일 구분 월간 검색수 + 월평균 클릭수/클릭률 + 경쟁 정도 제공.

단계별 사용법:

  1. searchad.naver.com → 네이버 광고 계정 생성 (무료)
  2. 도구 → 키워드도구
  3. 키워드 입력 → 결과 확인
  4. PC/모바일 비율 확인: 모바일 비중이 높으면 모바일 최적화 콘텐츠 필요
  5. 연관 키워드 목록으로 한글 롱테일 발굴

4. 검색량(수요) 측정 — 숫자 읽는 법 {#4}

절대량 vs 상대지수 구분

도구 제공 값 유형 절대량 여부
구글 트렌드 0~100 상대지수 X
네이버 데이터랩 0~100 상대지수 X
구글 키워드플래너 월간 평균 검색량 (범위) O (근사값)
네이버 검색광고 키워드도구 월간 검색수 O
구글 Search Console 실제 노출·클릭수 O (내 사이트 한정)

신생 AI 키워드 — 데이터가 얇을 때

MCP, Agentic AI 같은 신생 개념은 아직 검색량이 적거나 데이터가 축적되지 않아 키워드플래너에서 "데이터 없음"으로 나올 수 있다. 이 경우:

  1. 구글 트렌드 "급상승" 탭에서 트렌드 방향 확인
  2. GitHub Star 증가 속도, Reddit/Hacker News 게시물 반응 참고 (정량적 측정 방법은 아직 표준화되지 않았으나 방향 신호로 활용)
  3. 3개월 후 같은 키워드를 다시 키워드플래너에서 확인 → 데이터 생성 여부 모니터링

검색량 절대값보다 중요한 것

내 블로그스팟의 현재 체급 대비 상대 판단이 더 중요하다.

  • 월 1,000 검색 키워드도, 경쟁 문서가 10개라면 충분히 도전 가능.
  • 월 100,000 검색 키워드도, 경쟁 문서가 50,000개이고 모두 대형 도메인이면 의미없다.
  • 초기 블로그스팟은 월 100~1,000 검색의 롱테일 키워드부터 공략한다.

5. 경쟁강도(공급) 측정 — 이길 수 있는 싸움인가 {#5}

5-1. intitle: / allintitle: 연산자

구글 검색창에 직접 입력해 경쟁 문서 수를 확인하는 가장 빠른 방법.

  • intitle:Claude Code 사용법 → 제목에 "Claude Code 사용법"이 들어간 문서 수
  • allintitle:Claude Code 사용법 한국어 → 제목에 세 단어 모두 포함된 문서 수

결과 숫자 해석 기준 (절대 기준 아님, 참고용):

allintitle 결과 경쟁 강도 블로그스팟 도전 가능성
100 이하 매우 낮음 즉시 도전
100~1,000 낮음 도전 권장
1,000~10,000 중간 콘텐츠 품질이 관건
10,000 이상 높음 롱테일로 분기 필요

5-2. 키워드인사이트 유형 도구의 경쟁도 환산

도구별로 다르지만 일반적으로 "월간 검색수 대비 문서수 비율"을 0~100%로 환산한다.

대표적 6등급 분류 (키워드인사이트 기준):

  • Best Of Best (100% 초과): 문서수에 비해 검색량이 압도적으로 많음. 최우선 공략.
  • Best (80~100%): 황금 구간. 도전 가치 높음.
  • Good (60~80%): 도전 가능.
  • Normal (40~60%): 보통.
  • Not Bad (20~40%): 경쟁 있음.
  • Bad (20% 미만): 경쟁 대비 수요가 작음.

[주의] 이 등급은 해당 도구 전용 라벨링이며 산업 표준이 아님. 수치 자체보다 비율의 방향을 참고하라.

5-3. 상위 노출 글의 품질 경쟁 요소

경쟁강도는 문서 수만이 아니다. 상위 노출 문서의 품질도 확인해야 한다.

  • 글 길이: 2,000~4,000자(한글 기준) vs 500자 짜리 박사 글
  • 코드 예제 포함 여부: AI/개발자 콘텐츠에서 코드 없는 글은 경쟁력 약함
  • 최신성: Claude Code 같은 도구는 버전 변화가 빠름. 2년 전 글 vs 최신 글
  • 내부 링크 구조: 시리즈물로 연결된 글 vs 단독 글

6. 시즈널리티·트렌드 — AI 분야의 시간 전략 {#6}

AI 분야 이벤트성 급상승 패턴

AI 분야는 일반 블로그와 달리 계절성보다 이벤트 주기가 중요하다.

주요 급상승 트리거:

  • 신모델/신버전 발표 (Claude 4, GPT-5 등)
  • 새로운 도구/프로토콜 출시 (MCP 발표 직후 등)
  • 주요 기업의 정책 변경 (가격 변동, API 변경)
  • 바이럴 데모·튜토리얼 영상 확산

선점 전략:

  1. 공식 채널(Anthropic 블로그, OpenAI 블로그, GitHub 릴리스 노트) RSS/알림 구독
  2. 발표 당일~48시간 내 첫 글 발행이 핵심. 경쟁자보다 먼저 색인되는 것이 목표.
  3. 이벤트형 키워드는 단기 트래픽이 폭발하지만 휘발성이 강하다. 장기 트래픽을 위한 에버그린 키워드와 혼용할 것.

AI 분야 상시 검색 키워드 유형 (에버그린)

유형 예시 특성
설치/셋업 가이드 "Claude Code 설치 방법" 도구 존재하는 한 지속 검색
에러/문제해결 "MCP server 연결 안될 때" 사용자 급증할수록 검색 증가
비교글 "Claude Code vs Cursor" 의사결정 직전 사용자 유입
개념 정의 "Agentic AI 뜻" 신규 사용자 지속 유입

AI 이벤트 대응 키워드 캘린더 (운영 가이드)

매주: GitHub Trending, Hacker News 상위 AI 관련 글 모니터링
매월: 주요 AI 기업 블로그 신규 발표 확인
분기: 구글 트렌드에서 분야 전체 키워드 상승/하락 추이 점검

7. 키워드 발굴 10가지 방법 {#7}

방법 1: 구글 자동완성 + 연관검색어

구글 검색창에 키워드 입력 후 드롭다운 자동완성 목록 수집. 결과 페이지 하단의 "관련 검색어"도 확인.

  • "Claude Code " 뒤에 알파벳 a~z, 한글 가·나·다 순으로 입력해 완성어 목록 수집
  • "Claude Code 에러", "Claude Code 설치", "Claude Code 사용법" 등 발굴

방법 2: 네이버 자동완성 + 연관검색어

동일 방법으로 네이버에서 수행. 한글 사용자의 AI 키워드 표기 방식 파악에 유용.

방법 3: 구글 "People Also Ask(관련 질문)" 마이닝

검색 결과 중간의 "사람들이 자주 묻는 질문" 섹션. 클릭할수록 질문이 확장됨. 정보형 롱테일 키워드의 보고.

  • 질문을 그대로 제목으로 쓰면 구글이 직접 답변으로 표시(Featured Snippet) 노릴 수 있음.

방법 4: 경쟁 블로그/유튜브 역설계

내 분야 상위 블로그, 유튜브 채널의 인기 글·영상 제목을 분석해 사용 키워드 추출.

  • Ubersuggest, Ahrefs 무료 버전으로 경쟁 사이트의 상위 페이지 확인 가능.

방법 5: Reddit, Hacker News, Discord 질문 마이닝

실제 사용자들이 AI 툴에 대해 무엇을 묻는지 그대로 나온다. 커뮤니티 질문을 키워드화.

  • Reddit 검색: site:reddit.com "Claude Code" 또는 r/ClaudeAI, r/LocalLLaMA
  • Hacker News 검색: hn.algolia.com

방법 6: GitHub 이슈·README 용어 수집

오픈소스 AI 도구의 GitHub 이슈(Issues), Discussions에서 사용자들이 실제로 쓰는 기술 용어와 문제 상황 파악.

방법 7: 공식 문서 용어 추출

Claude API 문서, MCP 공식문서 등에서 핵심 용어·개념 추출 → 해당 개념을 검색하는 사람들 타겟.

방법 8: "vs", "error", "how to", "vs" 패턴 적용

시드 키워드 + 수식어 조합으로 롱테일 대량 생산:

  • Claude Code + error → 에러 해결 시리즈
  • Claude Code + vs Cursor → 비교 시리즈
  • Claude Code + how to (영문) → 튜토리얼 시리즈
  • Claude Code + 무료 → 가격 관련 시리즈

방법 9: 유튜브 검색 자동완성

유튜브 검색창에서도 자동완성 확인. 영상 콘텐츠와 블로그 콘텐츠는 겹치는 키워드가 많아 검증 도구로 유용.

방법 10: AI로 키워드 확장

Claude, ChatGPT에 "이 주제(예: MCP server)에 대해 초보자가 가장 많이 검색할 것 같은 질문 20개를 한국어와 영어로 각각 생성해줘" 요청 → 초기 후보 목록 빠르게 생성.

8. 영어 vs 한글 키워드 분기 전략 {#8}

AI 툴 분야는 영어 원어와 한글 표기가 혼재해 어느 언어로 글을 쓸지 결정하는 것 자체가 전략이다.

[주의] 아래는 측정 방법론이며, 특정 키워드의 영어/한글 검색량 차이 실측 데이터는 직접 확인이 필요하다.

분기 판단 도구 구분

언어 주 측정 도구 보조 도구
영문 키워드 구글 키워드플래너, 구글 트렌드 Ubersuggest, Ahrefs
한글 키워드 네이버 검색광고 키워드도구, 네이버 데이터랩 블랙키위

분기 판단 기준

  1. 구글 트렌드에서 영문/한글 동시 비교: "Claude Code"와 "클로드 코드"를 같은 그래프에. 어느 쪽이 상승 중인지 확인.
  2. 네이버 검색광고 도구에서 한글 표기별 검색수 비교: "클로드 코드" vs "클로드코드" vs "claude code" (네이버에서도 영문 검색 존재)
  3. 실전 판단 기준:
    • 한글 검색량 > 영문 검색량 (한국 독자 중심) → 한글 글 + 제목에 한글 키워드
    • 영문 검색량이 압도적 → 영문 글 고려 (단, 글로벌 경쟁 강함)
    • 한글 검색량이 있지만 경쟁 문서 거의 없음 → 한글로 선점 (가장 유리한 경우)

AI 분야 영어/한글 표기 혼재 사례

원어 한글 표기 예시 전략
Claude Code 클로드 코드, 클로드코드 둘 다 제목/본문에 포함
MCP (Model Context Protocol) MCP, 엠씨피, MCP 서버 "MCP 서버"가 실용적
Agentic AI 에이전틱 AI, 에이전트 AI 한글 표기 불안정 → 영문 병기
Vibe Coding 바이브코딩, 바이브 코딩 국내 커뮤니티 표기 확인

9. 키워드 조합·토픽 클러스터 {#9}

메인 키워드 + 수식어 조합

시드키워드: Claude Code
+ 행동: 설치, 사용법, 튜토리얼, 예제, 실습
+ 대상: 초보자, 파이썬, 맥OS, 윈도우
+ 문제: 에러, 안될때, 느릴때, 대안
+ 비교: vs Cursor, vs GitHub Copilot, vs Windsurf
+ 가격: 무료, 유료, 요금제
+ 시기: 2025, 2026, 최신

→ 생성 롱테일: "Claude Code 맥OS 설치 방법 초보자", 
                "Claude Code 파이썬 자동화 예제",
                "Claude Code 에러 해결 방법",
                "Claude Code vs Cursor 2026 비교"

토픽 클러스터 구조

필러(Pillar) 페이지: 주제 전체를 아우르는 종합 가이드. 내부링크의 허브. 클러스터(Cluster) 페이지: 필러의 세부 주제를 각각 깊게 다루는 개별 글.

AI 분야 토픽 클러스터 예시:

[필러] Claude Code 완전 가이드 (종합 허브)
  └─ [클러스터] Claude Code 설치 방법 (맥OS / 윈도우 / 리눅스)
  └─ [클러스터] Claude Code 첫 번째 프로젝트 만들기
  └─ [클러스터] Claude Code 단축키·슬래시 명령어 총정리
  └─ [클러스터] Claude Code MCP 연동하기
  └─ [클러스터] Claude Code vs Cursor 비교
  └─ [클러스터] Claude Code 자주 발생하는 에러 해결
  └─ [클러스터] Claude Code 활용 사례 모음

이 구조의 장점:

  • 필러 페이지가 내부링크를 받아 구글에서 주제 권위 인정
  • 각 클러스터가 독립적으로 롱테일 검색에서도 유입
  • 독자 체류시간·내부 이동 증가 → 품질 신호

10. 키워드 → 블로그스팟 글쓰기 → 유입 연결 {#10}

블로그스팟 온페이지 최적화 체크 (공식 문서 기반)

전제 조건 확인 (색인의 출발점):

  • Blogger 설정 → 개인정보 보호 → "검색엔진에 표시됨" ON
  • 이것이 꺼져 있으면 구글/빙 색인 자체가 차단됨.

제목 최적화:

  • 60자 이내 유지 (검색 결과에서 잘리지 않게)
  • 타겟 키워드를 제목 앞부분에 배치
  • 예: "Claude Code 설치 방법 — 맥OS 완전 가이드 2026"

URL(퍼머링크) 설정:

  • 짧고 명확한 영문 키워드 사용 (블로그스팟 편집 화면에서 직접 수정 가능)
  • 좋은 예: /claude-code-install-guide
  • 나쁜 예: /2026-06-01-claude-code-설치방법-완전가이드-블로그스팟

이미지 최적화:

  • 모든 이미지에 대체텍스트(Alt text) + 이미지 제목 부여
  • 키워드를 대체텍스트에 자연스럽게 포함

본문 키워드 배치:

  • 첫 100자 이내에 타겟 키워드 등장
  • 소제목(H2, H3)에 키워드 변형 포함
  • 자연스러운 밀도 유지 (과최적화 회피: 같은 키워드를 억지로 반복 금지)
  • 1글 1키워드 원칙: 한 글에서 하나의 주요 키워드에 집중

Blogger 라벨(Labels) 활용:

  • 라벨 = 카테고리 역할. 관련 글을 그룹화해 내부링크 구조 형성.
  • 예: "Claude Code", "MCP", "Agentic AI" 라벨로 시리즈 묶기

발행 후 순위 추적·재최적화

  1. Search Console에서 해당 글의 노출·클릭·순위 모니터링 (2~4주 뒤부터 데이터 생성)
  2. 순위 6~15위 유지 중인 글: 제목 수정, 본문 보강, 내부링크 추가 → 재최적화
  3. 노출 있는데 클릭 안 되는 글: 제목·메타 설명을 더 매력적으로 수정
  4. 완전히 순위 없는 글: 키워드 난이도 재검토, 경쟁 문서 재분석

11. 실전 워크플로우 — 처음부터 끝까지 {#11}

전체 프로세스 5단계

1단계: 시드 키워드 도출
2단계: 검색량·경쟁도 확인
3단계: 검색 의도 분류
4단계: 롱테일 확장 + 토픽 클러스터 설계
5단계: 의도별 콘텐츠 매핑 → 발행

워크스루 예제: "MCP server"

1단계: 시드 키워드

  • 원하는 주제: Model Context Protocol (MCP)

2단계: 검색량·경쟁도

  • 구글 트렌드: "MCP server" 급상승 확인 (2024년 말 이후)
  • 구글 키워드플래너: "MCP server" 월간 검색수 범위 확인
  • 네이버 검색광고 도구: "MCP 서버", "엠씨피" 한글 검색수 확인
  • allintitle: 연산자: allintitle:MCP server 설정 구글에서 결과수 확인

3단계: 검색 의도 분류

  • "MCP server 이란" → 정보형 (개념 설명 글)
  • "MCP server 설치" → 정보형/행동형 (튜토리얼 글)
  • "MCP server 연결 에러" → 문제해결형 (트러블슈팅 글)
  • "MCP server vs 일반 API" → 비교형 글

4단계: 롱테일 확장

  • "MCP server Claude Code 연동 방법"
  • "MCP server 직접 만들기 파이썬 예제"
  • "MCP server 안될때 해결방법"
  • "로컬 MCP server 무료 설정"

5단계: 콘텐츠 매핑

  • 필러: "MCP 서버 완전 가이드" (개념 + 설치 + 활용 + 트러블슈팅 링크 허브)
  • 클러스터 1: "MCP 서버 설치·설정 방법 단계별"
  • 클러스터 2: "파이썬으로 MCP 서버 직접 만들기"
  • 클러스터 3: "Claude Code에 MCP 서버 연동하기"
  • 클러스터 4: "MCP 서버 자주 발생하는 에러 해결"

12. 1페이지 실전 체크리스트 {#12}

키워드 선정 전

  • 타겟 독자가 실제로 검색창에 치는 말을 먼저 상상했는가?
  • 대표 키워드가 아니라 롱테일(3단어 이상)로 출발했는가?
  • 구글 트렌드에서 해당 키워드가 상승 중인가, 하락 중인가 확인했는가?

검색량·경쟁도 확인

  • 구글 키워드플래너 또는 네이버 검색광고 도구로 월간 검색수 확인
  • allintitle:키워드 구글 검색으로 경쟁 문서 수 확인
  • 상위 노출 글의 품질(길이, 코드예제, 최신성)을 직접 읽어봤는가?

검색 의도 확인

  • 이 키워드의 의도가 정보형/탐색형/거래형 중 어느 것인가 결정했는가?
  • 의도에 맞는 콘텐츠 형식을 선택했는가?

영어/한글 분기

  • 영문 vs 한글 표기 중 어느 쪽 검색량이 더 많은지 확인했는가?
  • 두 언어를 본문에 모두 포함할 수 있는가?

블로그스팟 발행 전

  • Blogger 설정 → "검색엔진에 표시됨" ON 확인
  • 제목이 60자 이내이고 키워드가 앞부분에 있는가?
  • URL(퍼머링크)이 짧은 영문 키워드로 설정됐는가?
  • 모든 이미지에 대체텍스트를 입력했는가?
  • 본문 첫 100자 이내에 타겟 키워드가 등장하는가?
  • 관련 라벨(Labels)을 설정했는가?
  • 같은 주제 이전 글에 이번 글 링크를 추가했는가? (내부링크)

발행 후

  • 2~4주 후 Search Console에서 노출·클릭·순위 확인 일정 잡았는가?
  • 순위 6~15위 글은 재최적화 대상으로 표시했는가?

13. 주의사항 및 반증된 통념 {#13}

딥리서치(3.1M 토큰, 106개 에이전트 검증) 과정에서 일반적으로 통용되지만 실제로는 근거가 없거나 반증된 주장들.

반증된 주장 (믿지 말 것)

"블로그스팟은 구글 소유라 SEO가 유리하다"

  • 검증 결과: 3표 만장일치 기각. 구글이 자사 플랫폼에 특별 혜택을 주지 않는다. 품질과 관련성이 순위를 결정한다.

"블로그스팟 색인 누락률이 99%에 달한다"

  • 검증 결과: 만장일치 기각. 설정이 올바르고 콘텐츠 품질이 있다면 정상 색인된다. 특정 사례를 일반화한 주장.

"네이버 데이터랩이 시간대별·연령별·성별 세분화를 제공한다"

  • 검증 결과: 만장일치 기각. 데이터랩 검색어트렌드는 기간별 상대지수만 제공. 쇼핑인사이트에서 일부 세분화 가능하나 일반 검색어트렌드는 해당 없음.

"검색 의도는 정보형 6070%, 거래형 2030%로 고정된 비율이다"

  • 검증 결과: 부분 기각. 분야와 키워드마다 의도 분포가 크게 다르며 고정 비율 적용은 무의미.

미확정 영역 (추가 검증 필요)

  • 영어 vs 한글 키워드 분기의 실측 데이터: "Claude Code"와 "클로드 코드"의 실제 검색량 차이를 보여주는 1차 데이터가 없다. 도구를 통해 직접 측정할 것.
  • GitHub/Reddit/HN 화제성 → 검색 수요 전환 방법론: 트렌드 선행지표로 활용 가능하지만 정량적 방법론은 표준화되지 않음.
  • 낮은 도메인권위 극복의 검증된 경로: 롱테일·온페이지 기본기 외의 실증된 방법(내부링크, E-E-A-T, 발행 빈도 효과)은 추가 검증 필요.
  • 블랙키위 검색량 산출 방식: 확정 출처에서 확인되지 않음. 직접 사용해 네이버 공식 수치와 비교 검증 권장.

00MCP가 뭐예요?

MCP(Model Context Protocol, 모델 컨텍스트 프로토콜)는 Claude Code에게 원래 없던 새 능력(도구)을 끼워주는 표준 규격입니다. 예를 들면 이슈 트래커 검색하기, 데이터베이스 조회하기, 웹 브라우저 조종하기 같은 일들이죠.

이런 도구들은 MCP 서버라는 작은 프로그램에서 제공됩니다. 서버는 내 컴퓨터에서 직접 실행되거나, 인터넷에 올라가 있는 서비스 형태로 동작합니다.

쉽게 말하면

MCP는 노트북의 USB 포트와 같습니다. Claude Code는 본체, MCP 서버는 거기에 꽂는 외부 기기(키보드·웹캠·외장하드)예요. 포트 규격(MCP)이 정해져 있으니, 규격만 맞으면 어떤 도구든 꽂아서 바로 쓸 수 있습니다.

이 가이드는 MCP 서버 하나를 처음부터 끝까지 연결하는 과정을 보여줍니다. 다 읽고 나면 서버를 연결해 응답을 받아보고, 설정이 컴퓨터 어디에 저장되는지 알고, 자주 나는 연결 오류를 직접 고칠 수 있게 됩니다.

01이 글을 끝내면 할 수 있는 것

  • MCP 서버를 Claude Code에 추가하고, 연결됐는지 직접 확인할 수 있어요.
  • 설정 파일이 컴퓨터 어디에 저장되는지 알고, 적용 범위를 바꿀 수 있어요.
  • "연결 실패" 같은 오류가 나도 원인을 찾아 스스로 고칠 수 있어요.

02시작하기 전에 (준비물)

딱 두 가지만 있으면 됩니다.

1. Claude Code 설치 + 로그인 — 아직이라면 공식 빠른 시작 가이드를 먼저 따라 하세요.

2. 터미널 열기 — 아무 폴더에서나 열면 됩니다. 빈 폴더여도 괜찮아요.

참고

터미널(Terminal)은 명령어를 글자로 입력해 컴퓨터를 다루는 검은 창입니다. macOS는 "터미널" 앱, Windows는 "PowerShell" 또는 "명령 프롬프트"를 쓰면 됩니다.

03먼저 알아둘 핵심 용어 3개

아래 세 단어만 알아두면 이 글이 훨씬 쉬워집니다. 외우지 말고 눈에만 익혀두세요.

호스팅형 서버 http
인터넷 주소(URL)에 올라가 있는 서버. 내 컴퓨터에 설치할 필요 없이 주소만 등록하면 됩니다.
로컬형 서버 stdio
내 컴퓨터에서 프로그램으로 직접 실행되는 서버. 브라우저·파일처럼 내 컴퓨터 자원이 필요할 때 씁니다.
스코프 scope
이 서버를 "어디까지" 쓸지 정하는 범위. 이 프로젝트만(local) / 내 모든 프로젝트(user) / 팀 전체(project).

04서버 추가하고 연결 확인하기

첫 연습 상대는 Claude Code 공식 문서 검색 서버(claude-code-docs)입니다. 로그인이나 특별한 설정이 필요 없어서, 처음 연습용으로 딱 좋아요.

모든 서버는 추가 → 상태 확인 → 사용 순서가 똑같습니다. 마지막에 정리(삭제)는 선택이고요. 천천히 하나씩 따라 해봅시다.

  1. 서버 추가하기

    아래 명령을 터미널에 입력하세요. claude 대화 세션 안이 아니라, 일반 터미널에서 실행해야 합니다. (대화를 시작하기 전에 미리 설정하는 단계라서 그래요.)

    터미널 · bash
    claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp

    이 명령을 한 조각씩 읽어보면:

    • claude mcp add — "MCP 서버를 등록해줘"라는 뜻이에요.
    • --transport http — 이 서버는 인터넷 주소형(호스팅형)이라는 표시.
    • claude-code-docs — 내가 붙이는 별명. docs처럼 아무 이름이나 OK. 나중에 이 이름으로 서버를 부릅니다.
    • https://code.claude.com/docs/mcp — 서버가 올라가 있는 실제 주소.
    결과Added HTTP MCP server claude-code-docs ... to local config 같은 문구가 뜨면 성공입니다. "local config"는 이 프로젝트에서, 나에게만 등록됐다는 뜻이에요.
  2. 연결 상태 확인하기

    방금 추가한 서버가 목록에 잘 들어갔는지, 그리고 연결됐는지 확인합니다.

    터미널 · bash
    claude mcp list

    서버 이름 옆에 아래와 같은 상태 표시가 함께 나옵니다.

    상태의미
    ✓ Connected연결 성공, 바로 사용 가능. claude-code-docs는 이게 나와야 정상이에요.
    ! Needs authentication서버는 닿았지만 로그인이 필요합니다. (아래 4번 Sentry 예시 참고)
    ✗ Failed to connect서버가 응답하지 않음. 문제 해결을 보세요.
    ✗ Connection error연결 시도 중 오류 발생. 문제 해결을 보세요.
    ⏸ Pending approval아직 승인하지 않은 프로젝트 공용 서버입니다.
  3. 실제로 써보기

    이제 대화 세션을 시작합니다. (이번엔 claude를 그냥 입력해서 들어가요.)

    터미널 · bash
    claude

    그리고 Claude에게 서버 이름을 콕 집어서 부탁해봅니다.

    Claude에게 입력
    claude-code-docs 서버를 사용해서 MCP_TIMEOUT이 무슨 일을 하는지 찾아줘
    참고

    원래는 서버 이름을 굳이 말 안 해도 Claude가 알아서 적절한 도구를 고릅니다. 여기서 이름을 콕 집은 건, 다른 도구가 아니라 방금 만든 서버를 확실히 거치게 하려는 연습용이에요.

    Claude가 그 서버를 처음 쓸 때 도구 사용 권한을 물어봅니다. 승인하면 계속 진행돼요. Claude의 답변에 표시되는 도구 호출에 서버 이름이 붙어 있으면, 답이 그 서버를 거쳐 나온 거라는 증거입니다.

  4. (선택) 서버 삭제하기

    연습이 끝나 더 안 쓸 거라면 지워도 됩니다. 안 지워도 무방해요.

    터미널 · bash
    claude mcp remove claude-code-docs
    팁

    연결된 서버는 매번 대화 시작 때마다 도구 정보가 불려와서 대화 공간(컨텍스트)을 조금씩 차지합니다. 안 쓰는 서버를 정리하면 그 공간이 비워져요.

05설정은 어디에 저장되나요?

claude mcp add 명령은 서버 정보를 설정 파일에 적어둡니다. 기본값은 local 스코프 — 즉 나에게만, 지금 이 프로젝트에서만 적용됩니다.

더 넓게 쓰고 싶으면 옵션을 붙이면 돼요. --scope user는 내 모든 프로젝트, --scope project는 팀 전체와 공유.

참고

claude mcp add는 어떤 터미널에서든(PowerShell·명령 프롬프트 포함) 똑같이 동작합니다. 이미 claude 대화 세션에 들어와 있다면, 세션 안에서는 /mcp 명령으로 서버를 확인·관리하세요.

설정 파일 위치 (스코프별)

직접 편집할 일은 거의 없지만, 어디 있는지 알아두면 디버깅과 버전 관리에 도움이 됩니다.

스코프저장 파일적용 대상
local~/.claude.json 안의 이 프로젝트 항목나만, 이 프로젝트만 (기본값)
project프로젝트 폴더의 .mcp.json이 프로젝트를 받은 모든 사람
user~/.claude.json 맨 위 mcpServers 항목나만, 내 모든 프로젝트

Windows에서 ~/.claude.json은 %USERPROFILE%\.claude.json을 가리킵니다. 어느 스코프에 저장됐는지 보려면 claude mcp get claude-code-docs를 실행하세요.

06적용 범위(스코프) 바꾸기

스코프는 추가할 때 정해지면 나중에 바로 못 바꿉니다. 바꾸려면 지웠다가 새 스코프로 다시 추가해야 해요. 먼저 기존 local 항목을 지웁니다. (4번 마지막에서 이미 지웠다면 건너뛰세요.)

터미널 · bash
claude mcp remove claude-code-docs --scope local

내 모든 프로젝트에서 쓰기 (user)

어느 프로젝트를 열든 항상 켜져 있게, 단 나에게만:

터미널 · bash
claude mcp add --scope user --transport http claude-code-docs https://code.claude.com/docs/mcp

팀과 공유하기 (project)

project 스코프로 추가하면 프로젝트 폴더에 .mcp.json 파일이 만들어집니다.

터미널 · bash
claude mcp add --scope project --transport http claude-code-docs https://code.claude.com/docs/mcp

이 .mcp.json을 Git에 커밋해두면, 동료가 저장소를 받아 Claude Code를 켤 때 "이 서버 승인할래요?" 안내가 뜨고, 승인하면 그쪽에서도 연결됩니다.

07다른 종류의 서버 예시

지금까지는 로그인 없는 호스팅형 서버였어요. 이제 나머지 두 가지 흔한 형태를 봅니다. 흐름은 똑같이 추가 → 확인 → 사용입니다.

예시 1. 로컬형 서버 (Playwright 브라우저)

로컬형(stdio) 서버는 내 컴퓨터에서 프로그램으로 켜지는 서버입니다. 브라우저·파일·DB처럼 내 컴퓨터 자원이 필요할 때 써요.

Playwright MCP 서버는 Claude에게 직접 조종할 수 있는 브라우저를 줍니다. 계정도 필요 없어요. 단, npx로 실행되므로 Node.js 18 이상이 깔려 있어야 합니다.

  1. Playwright 서버 추가
    터미널 · bash
    claude mcp add playwright -- npx -y @playwright/mcp@latest

    호스팅형과 다른 점 세 가지:

    • --transport 옵션이 없습니다. 로컬형은 기본 방식(stdio)을 쓰거든요.
    • -- 뒤에 오는 건 전부 서버를 켜기 위해 실행할 명령입니다.
    • -y는 npx에게 "묻지 말고 바로 설치해"라는 뜻이에요.
  2. 연결 확인

    "Added" 문구는 등록됐다는 뜻이지 실행됐다는 뜻이 아니에요. 상태를 확인합니다.

    터미널 · bash
    claude mcp list
    주의

    처음엔 npx가 패키지를 내려받는 동안 ✗ Failed to connect로 보일 수 있어요. 잠깐 기다렸다 다시 실행하면 연결됩니다.

  3. 브라우저로 시켜보기
    Claude에게 입력
    playwright로 https://example.com 을 열고 페이지 제목을 알려줘

    브라우저 창이 떠서 직접 움직이는 걸 볼 수 있어요. Claude 답변의 도구 호출에는 playwright라는 서버 이름과 browser_navigate 같은 동작이 함께 표시됩니다.

예시 2. 로그인이 필요한 서버 (Sentry)

Sentry·Linear·Notion 같은 서비스는 MCP 서버가 OAuth 로그인 뒤에 있습니다. 주소를 추가한 뒤, 브라우저에서 로그인하는 과정이 한 단계 더 있어요. 아래는 Sentry 예시입니다.

  1. 서버 추가

    추가 명령은 문서 서버와 똑같고, 주소만 Sentry 것으로 바꿉니다.

    터미널 · bash
    claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

    추가 후 claude mcp list를 보면 ! Needs authentication이 뜹니다. 정상이에요 — 다음 단계에서 로그인하면 됩니다.

  2. 브라우저에서 로그인

    대화 세션을 시작하고 MCP 패널을 엽니다.

    Claude 세션 안
    /mcp

    목록에서 sentry를 고르고 Enter → Authenticate를 선택하면 브라우저에 Sentry 로그인 화면이 열립니다. 거기서 승인하면, Claude Code로 돌아왔을 때 상태가 연결됨으로 바뀝니다.

  3. 사용하기

    내가 접근할 수 있는 Sentry 프로젝트가 뭐가 있어?처럼 그 서비스가 필요한 질문을 해보고, 답변에 sentry 서버 이름이 붙은 도구 호출이 있는지 확인하세요.

참고

OAuth 대신 고정 토큰으로 인증하는 서버는 추가할 때 --header "Authorization: Bearer <토큰>"을 붙여서 토큰을 전달합니다. (예: GitHub)

08설정 파일 직접 작성하기 (.mcp.json)

모든 스코프는 같은 JSON 형식을 씁니다. 그중 .mcp.json(프로젝트 스코프)은 저장소에 함께 들어가서 "코드처럼 관리되는 설정" 역할을 하므로, 손으로 직접 써볼 만합니다.

프로젝트 폴더 맨 위에 .mcp.json 파일을 만들고 아래처럼 작성하세요. 이 글에 나온 두 서버를 한꺼번에 정의한 예시입니다.

json · .mcp.json
{
  "mcpServers": {
    "claude-code-docs": {
      "type": "http",
      "url": "https://code.claude.com/docs/mcp"
    },
    "playwright": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}
  • 호스팅형(http) 서버는 url에 접속할 주소를 적습니다.
  • 로컬형(stdio) 서버는 command와 args에 실행할 프로그램을 적습니다.

저장한 뒤 그 프로젝트에서 Claude Code를 새로 시작하세요. 시작할 때 .mcp.json을 읽고, 프로젝트 공용 서버는 처음 한 번 승인을 물어봅니다. (낯선 저장소가 내 컴퓨터에서 멋대로 프로그램을 켜지 못하게 하는 안전장치예요.) 승인하거나, 놓쳤다면 /mcp로 나중에 승인하면 됩니다.

09다른 환경에서 연결하기

이 가이드는 claude mcp 명령어(CLI)를 썼지만, Claude Code의 모든 환경에서 MCP 서버를 연결할 수 있어요.

  • Claude Code 데스크톱 앱 — Connectors(커넥터) 화면에서 추가.
  • Claude Desktop 채팅 앱 — macOS/WSL에서 claude mcp add-from-claude-desktop으로 기존 설정을 가져오기.
  • VS Code — "MCP로 외부 도구 연결하기" 문서 참고.
  • Claude Code 웹 — 저장소의 .mcp.json을 읽어옵니다.
  • Claude.ai — claude.ai/customize/connectors에서 추가한 커넥터가, 같은 계정으로 로그인하면 CLI에서도 자동으로 불러와집니다.

10문제 해결 (잘 안 될 때)

연결이 안 되면 먼저 상태부터 확인하세요. 세션 안이면 /mcp, 터미널이면 claude mcp list. 그다음 아래에서 내 증상을 찾아보세요. (제목을 누르면 펼쳐집니다.)

"No MCP servers configured"가 떠요▶

지금 폴더에서 서버를 못 찾았다는 뜻입니다. 흔한 원인:

  • 다른 프로젝트에서 추가했어요. local 스코프 서버는 추가한 그 폴더에만 묶입니다. 지금 폴더에서 다시 추가하거나, --scope user로 추가해 폴더에 안 묶이게 하세요.
  • 설정 파일을 엉뚱한 경로에 만들었어요. 올바른 위치는 ~/.claude.json과 <프로젝트>/.mcp.json뿐입니다.
"Failed to connect" 또는 "Connection error"▶

서버가 안 켜졌거나 주소가 응답하지 않는다는 뜻입니다. 호스팅형이라면 먼저 주소가 내 컴퓨터에서 닿는지 확인하세요.

터미널 · bash
curl -I https://mcp.sentry.dev/mcp
  • 404 / 405 — 서버는 살아있어요. (많은 MCP 주소가 POST만 받아서 그래요. 닿는다는 증거입니다.)
  • 401 / 403 — 서버는 살아있고 로그인이 필요합니다. (예시 2 참고)
  • 아무 응답 없음 — 주소와 네트워크를 다시 확인하세요.

로컬형 서버라면, 설정된 명령을 터미널에서 직접 실행해 오류 메시지를 보세요. 예: npx -y @playwright/mcp@latest

시작할 때 시간 초과(timed out)가 나요▶

기본 30초 안에 서버가 안 켜진 경우입니다. 로컬형은 npx가 패키지를 처음 받느라 느릴 수 있어요. 제한 시간을 MCP_TIMEOUT(밀리초)으로 늘리세요.

터미널 · bash
MCP_TIMEOUT=60000 claude
"Server already exists"가 떠요▶

같은 스코프에 같은 이름의 서버가 이미 있다는 뜻입니다. 기존 걸 지우거나, 다른 이름으로 추가하세요.

터미널 · bash
claude mcp remove claude-code-docs

여러 스코프에 같은 이름이 있으면 --scope로 어느 걸 지울지 정하면 됩니다.

연결은 됐는데 도구가 안 보여요▶

/mcp에서 서버를 골라 도구 목록을 보세요. 비어 있다면 보통 필수 환경변수(API 키 등)가 빠진 경우입니다. claude mcp add에 --env KEY=값을 붙이거나, .mcp.json의 env 항목에 적어주세요.

.mcp.json을 고쳤는데 반영이 안 돼요▶

.mcp.json은 세션 시작 때 읽힙니다. 파일을 고쳤으면 세션을 끄고 다시 켜세요. 예전에 서버 승인을 거절했다면, 프로젝트 승인 기록을 초기화하세요.

터미널 · bash
claude mcp reset-project-choices
OAuth 로그인이 실패하거나 브라우저가 안 열려요▶

/mcp에서 서버를 고르고 Authenticate를 다시 시도하세요. 브라우저가 자동으로 안 열리면, 터미널에 표시된 주소를 복사해 직접 여세요.
